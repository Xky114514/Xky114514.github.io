# 运营迭代需求文档（模块增强版）

> 文档版本：V2.1；文档状态：评审稿；更新日期：2026-09-06；适用角色：产品、运营、UI/UX、前端、后端、测试、数据；需求基线：《运营迭代需求》原文及当前 Super Admin 前端原型。

---

## 修订说明

本版本以原需求文档的模块、章节顺序和业务边界为基础进行补充，不对整个 Super Admin 系统做全面重构，也不扩展合同统计、模型用量、语音识别用量等与本次迭代无关的页面。

本次补充重点包括：

1. 明确原文各模块的页面位置、字段、数据口径、计算逻辑、展示规则和交互方式。
2. 将“数据看板”调整为一级菜单“运营工作台”，作为运营人员进入系统后的默认页面，并保留原有四个业务分类页签。
3. 将“问题案例”和“原因分析”调整为平级页签，原因分析统一命名为“问题归因分析”。
4. 优化原因标签分布和原因趋势，支持从原因标签下钻到关联租户与问题案例；移除独立的“平均识别率趋势”图。
5. 补充列表“操作”字段中各行操作按钮的点击反馈、抽屉内容、提交结果和状态刷新逻辑。
6. 表头、指标和配置项中的解释性文字改为问号悬浮提示，减少页面正文中的说明性内容。
7. 明确四类运营事项的优先级、多事项合并与关联规则、触发和恢复条件，以及必要的数据依赖。
8. 运营工作台列表不展示“问题描述”和“处理时限”；详细背景统一放入事项详情抽屉。

## 1. 产品目标

### 1.1 业务目标

- 运营人员进入系统后，能够优先看到由自己负责且需要处理的运营事项。
- 将试用、额度、合同、使用效果和系统配置问题集中到统一工作台处理。
- 帮助运营从问题案例定位原因，再从原因定位关联租户和具体案例。
- 统一字段命名、指标口径与交互反馈，使页面表达符合 B 端后台系统习惯。
- 在保证信息可理解的前提下降低页面密度，避免在列表或标题区域堆叠解释文字。

### 1.2 使用角色

| 角色 | 主要目标 | 主要操作 |
|---|---|---|
| 运营人员 | 查看并处理本人负责事项 | 筛选、查看详情、执行快捷操作、更新处理状态 |
| 运营负责人 | 了解全部事项和处理进度 | 查看全部待办、调整处理人、查看处理记录 |
| 产品/算法人员 | 分析问题案例及原因 | 查看原始内容、人工归因、重新归因、原因下钻 |
| 系统管理员 | 维护原因标签与系统配置 | 新增、编辑、启停原因标签，处理配置类事项 |

### 1.3 统一设计原则

- **待办优先**：默认展示“我的待办”，让运营先看到需要自己处理的内容。
- **分类与优先级分离**：四个页签代表业务分类，高、中、低代表处理紧急程度。
- **列表只放决策信息**：解释、背景、完整规则和处理记录放入悬浮提示或详情抽屉。
- **交互形成闭环**：每个操作均需有打开、填写、校验、提交、反馈和刷新过程。
- **数据口径可追溯**：指标应明确分子、分母、去重方式、时间范围和空值规则。

## 2. 页面结构调整

### 2.1 本次调整边界

| 页面/模块 | 调整内容 | 不在本次范围 |
|---|---|---|
| 运营工作台 | 从租户管理中独立为一级菜单，设为默认首页；保留四个分类页签 | 不重构其他一级菜单 |
| 销售业务分析 | “数据概览”“问题案例”“问题归因分析”平级展示 | 不修改销售业务之外的统计页面 |
| 采购业务分析 | “数据概览”“问题案例”“问题归因分析”平级展示 | 不修改采购业务之外的统计页面 |
| 问题案例 | 增加原始内容预览、人工原因标签和 AI 归因状态 | 不重构订单处理流程 |
| 问题归因分析 | 优化原因分布、原因趋势和关联租户下钻 | 不增加独立平均识别率趋势图 |
| 原因标签管理 | 说明改为问号提示；补齐新增、编辑、启停规则 | 不新增其他系统配置模块 |

### 2.2 运营工作台入口

- 一级菜单名称统一为“运营工作台”。
- 用户进入系统后默认路由为运营工作台，并默认选中“我的待办”。
- 工作台保留四个业务分类页签：试用转化、额度及合同履约、使用活跃与识别质量、系统运行与配置。
- 页签后的数字表示当前待办范围及筛选条件下的未完成事项数，不按租户去重。

### 2.3 销售与采购分析页签

销售业务分析和采购业务分析均使用以下平级结构：

1. 数据概览
2. 问题案例
3. 问题归因分析

“问题归因分析”不再作为“问题案例”的内部二级页签。切换页签时保留能够复用的时间、租户、内容类型和负责人筛选条件。

### 2.4 说明类信息展示规则

| 场景 | 展示方式 | 交互要求 |
|---|---|---|
| 表格字段存在特殊口径 | 字段名右侧显示问号图标 | 悬浮、点击或键盘聚焦后显示业务含义和口径 |
| 指标名称存在计算逻辑 | 指标名右侧显示问号图标 | 提示分子、分母、时间范围和空值规则 |
| 配置项存在使用限制 | 配置项右侧显示问号图标 | 提示影响范围、使用方式和注意事项 |
| 普通字段或通用操作 | 不显示问号 | 避免无意义图标造成视觉干扰 |

提示框最大宽度建议为 320 px，内容支持换行；再次点击、失焦或按 `Esc` 关闭。提示不得遮挡当前操作按钮，也不在页面标题下重复罗列同一段说明。

## 3. 产品需求

### 3.1 租户级图片订单占比

#### 3.1.1 功能说明

在销售业务分析和采购业务分析的数据概览中补充租户级图片订单数据，用于判断租户订单来源结构及图片识别场景占比。

#### 3.1.2 筛选条件

| 筛选项 | 选项/规则 |
|---|---|
| 时间范围 | 今日、昨日、本周、上周、本月、自定义 |
| 订阅状态 | 全部、试用、正式、停用 |
| 上线阶段 | 全部、待接入、实施中、已上线 |
| 客户成功经理 | 当前账号有权限查看的人员 |
| 租户 | 按租户名称包含匹配 |

#### 3.1.3 列表字段与口径

| 字段 | 字段定义/计算逻辑 | 展示与交互 |
|---|---|---|
| 租户名称 | 订单所属租户的正式名称 | 点击进入租户运营分析 |
| 提交订单数 | 当前筛选范围内有效订单总数 | 整数；支持排序 |
| 图片订单数 | 内容类型为图片的有效订单数 | 整数；支持排序 |
| 图片订单占比 | 图片订单数 ÷ 提交订单数 × 100% | 保留 1 位小数；支持升降序 |
| 商品名称识别率 | 正确识别商品名称的有效商品行数 ÷ 有效商品行总数 × 100% | 保留 1 位小数 |
| 数量识别率 | 正确识别数量的有效商品行数 ÷ 有效商品行总数 × 100% | 保留 1 位小数 |
| 备注识别率 | 正确识别备注的有效商品行数 ÷ 有效商品行总数 × 100% | 保留 1 位小数 |

#### 3.1.4 计算、展示与数据要求

- 有效订单指任务提交成功、未删除、未作废且非测试数据的订单。
- 同一订单包含多张图片时按 1 个图片订单计数，不按图片张数累计。
- 提交订单数为 0 时，图片订单数展示 `0`，图片订单占比展示“—”。
- 比率字段不得使用 `0%` 代替数据缺失或分母为 0。
- 默认按提交订单数倒序；点击图片订单占比表头后按占比排序，空值始终置底。
- 导出数据继承当前筛选条件，并包含图片订单数和图片订单占比。
- “图片订单占比”右侧显示问号，提示：“内容类型为图片的有效订单数占全部有效订单数的比例；无有效订单时不计算。”
- 数据依赖：订单唯一标识、租户标识、提交时间、订单状态、测试标识和标准化内容类型 `text/image/file`。

### 3.2 问题案例原始内容预览

#### 3.2.1 功能说明

运营或产品人员在问题案例列表中点击内容类型或“预览原始内容”，以抽屉方式查看任务最初提交的文本、图片或文件，便于判断识别结果与原因标签是否准确。

#### 3.2.2 问题案例列表字段

| 字段 | 字段定义 | 展示与交互 |
|---|---|---|
| 任务提交时间 | 任务首次提交时间 | `YYYY-MM-DD HH:mm` |
| 租户名称 | 案例所属租户 | 点击进入租户运营分析 |
| 来源群聊/下单客户 | 任务来源对象 | 超长省略，悬浮显示完整内容 |
| 内容类型 | 文本、图片、文件 | 点击打开原始内容预览 |
| 商品名称识别率 | 正确商品名称行数 ÷ 有效商品行数 | 低于 70% 使用风险色 |
| 数量识别率 | 正确数量行数 ÷ 有效商品行数 | 百分比 |
| 原因标签 | 当前案例有效原因标签，可多选 | 点击进入人工标签编辑 |
| 归因状态 | 待归因、归因中、已归因、归因失败 | 状态标签 |
| 归因来源 | AI、人工或“—” | 人工结果优先 |
| 操作 | 预览原始内容、编辑原因标签、重新归因 | 按权限与状态展示 |

#### 3.2.3 预览抽屉内容

| 内容类型 | 展示字段 | 交互 |
|---|---|---|
| 文本 | 原始文字、提交人、提交时间 | 支持复制全文 |
| 图片 | 原始图片、图片序号、提交时间 | 支持多图切换、放大、缩小和恢复原比例 |
| 文件 | 文件名、文件类型、文件大小、可解析内容 | 支持打开原文件；不支持预览时提示下载查看 |

抽屉同时展示任务编号、租户名称、AI 原始识别结果和人工最终确认结果，并提供“查看案例详情”入口。

#### 3.2.4 状态、权限与数据要求

- 加载中显示骨架或明确加载状态。
- 加载失败显示失败原因和“重新加载”按钮，不关闭抽屉。
- 原始文件已失效时显示“原始内容已失效”，不得展示空白区域。
- 无查看权限时不请求或不返回原始内容，并记录访问审计。
- 关闭抽屉后保留列表筛选、页码和滚动位置。
- 数据依赖：案例与原始任务关联标识、内容类型、原始内容或存储地址、文件元数据、提交人、提交时间、识别结果及人工确认结果。

### 3.3 人工原因标签与原因标签管理

#### 3.3.1 人工原因标签

问题案例允许运营人员人工补充或修正原因标签，用于纠正 AI 归因结果并沉淀可复用的结构化原因数据。

| 编辑字段 | 必填 | 规则 |
|---|---|---|
| 原因标签 | 否 | 可多选；只能选择已启用且适用于当前内容类型的系统标签 |
| 调整说明 | 否 | 最多 200 字；用于记录人工修改原因 |

保存规则：

1. 点击“编辑原因标签”打开抽屉，展示 AI 建议标签、当前有效标签和历史修改记录。
2. 保存前校验所选标签是否仍为启用状态。
3. 人工保存后，归因来源更新为“人工”并锁定结果，后续 AI 任务不得覆盖。
4. 删除全部标签并保存后，归因状态恢复为“待归因”，来源和置信度展示“—”。
5. 保存成功后刷新当前行、原因分析汇总指标和图表；失败时保留选择并展示错误原因。
6. 系统记录操作人、操作时间、变更前标签、变更后标签和调整说明。

#### 3.3.2 原因标签管理

页面位置：系统设置 → 原因标签管理。

原页面标题下“AI 与人工归因只能从启用的系统标签中选择”的常驻说明文字移除，改为标题右侧问号悬浮提示。

##### 列表字段

| 字段 | 字段定义 | 展示与交互 |
|---|---|---|
| 展示顺序 | 数值越小，标签在选择器和图表中越靠前 | 支持编辑 |
| 标签名称 | 原因标签的统一名称 | 支持搜索 |
| 适用内容类型 | 全部、文本、图片、文件 | 支持筛选 |
| 启用状态 | 是否允许用于新案例归因 | 开关与状态文字同步 |
| 近 30 天案例数 | 最近 30 天使用该标签的去重案例数 | 整数 |
| 更新时间 | 最近一次修改时间 | `YYYY-MM-DD HH:mm` |
| 操作 | 编辑、停用或启用 | 按当前状态展示 |

##### 新建/编辑字段

| 字段 | 必填 | 校验规则 |
|---|---|---|
| 标签名称 | 是 | 2～30 个字符；去除首尾空格；同一适用范围内不可重复 |
| 适用内容类型 | 是 | 全部、文本、图片、文件 |
| 展示顺序 | 是 | 1～999 的整数 |
| 启用状态 | 是 | 新建时默认启用 |
| 标签说明 | 否 | 最多 200 字；作为管理端提示和 AI 归因上下文 |

##### 操作交互与数据要求

- 点击“新建标签”打开编辑抽屉；成功后新增到列表并按展示顺序重排。
- 点击“编辑”打开当前标签信息；名称或适用类型变化时提示对后续归因的影响。
- 点击“停用”先二次确认；停用后不可用于新归因，但历史案例继续展示。
- 已有关联案例的标签不得物理删除。
- 点击启用开关与“启用/停用”文字操作使用同一状态变更逻辑。
- 数据依赖：标签 ID、名称、适用内容类型、顺序、状态、说明、创建/更新人及时间；案例标签关系需记录归因来源和有效状态。

### 3.4 AI 自动归因

#### 3.4.1 触发条件

有效任务处理完成后，同时满足以下条件时异步触发 AI 归因：

1. 商品名称识别率低于 70%。
2. 案例不存在人工锁定的归因结果。
3. 当前没有同一案例正在执行的归因任务。

历史案例批量归因沿用同一判断逻辑。

#### 3.4.2 输入与输出字段

| 类型 | 字段 | 用途/说明 |
|---|---|---|
| 输入 | 原始内容 | 文本、图片或文件的原始输入 |
| 输入 | AI 原始识别结果、人工最终结果、字段修改差异 | 判断商品、数量、单位、备注等识别偏差 |
| 输入 | 内容类型、文件类型、租户上下文 | 限定场景和标签范围 |
| 输入 | 已启用系统标签 | 限定模型输出，不允许生成自由标签 |
| 输出 | 推荐标签及置信度 | 标签 ID 数组；每个标签置信度为 0～1 |
| 输出 | 归因依据 | 简短证据摘要，不直接展示敏感原文 |
| 输出 | 归因状态 | 归因中、已归因、归因失败、待归因 |
| 输出 | 模型版本、归因时间、任务标识 | 用于追溯、幂等和重试 |

#### 3.4.3 执行、交互和口径

- AI 只能选择已启用且适用的系统标签，不得创建新标签。
- 归因任务异步执行，不阻塞订单或任务提交。
- 无法匹配有效标签时状态为“待归因”；执行失败时保存标准错误码和错误摘要。
- “重新归因”仅在归因失败或非人工锁定状态下展示；点击后确认并创建新任务。
- 重新归因过程中按钮显示加载状态并禁用；完成后刷新当前行。
- 同一案例同一时刻只允许一个有效任务；重复点击不得产生并发任务。
- 人工结果始终优先，重新归因不得覆盖人工锁定结果。
- 商品名称识别率 = 正确识别商品名称的有效商品行数 ÷ 有效商品行总数 × 100%。
- 有效商品行总数为 0 时不创建问题案例，也不触发自动归因。
- 案例按任务唯一标识去重；同一任务多次重试只保留一个当前有效案例。

### 3.5 问题归因分析

#### 3.5.1 功能说明

问题归因分析作为销售业务分析和采购业务分析中的独立平级页签，用于查看问题规模、主要原因、变化趋势及受影响租户，并可继续下钻到具体案例。

#### 3.5.2 筛选条件

| 筛选项 | 规则 |
|---|---|
| 时间范围 | 今日、本周、本月、自定义 |
| 统计粒度 | 日、周、月；根据时间范围给出推荐值 |
| 内容类型 | 全部、文本、图片、文件 |
| 文件类型 | 仅当内容类型为文件时可选 |
| 租户类型/指定租户 | 全部或权限范围内指定值 |
| 原因标签 | 全部或指定标签 |
| 归因状态 | 全部、待归因、归因中、已归因、归因失败 |
| 订阅状态/上线阶段 | 沿用租户主数据 |
| 客户成功经理 | 按负责人筛选 |

#### 3.5.3 汇总指标

| 指标 | 计算逻辑 | 展示规则 |
|---|---|---|
| 问题案例数 | 商品名称识别率低于 70% 的有效案例数，按案例 ID 去重 | 整数 |
| 已归因案例数 | 至少存在 1 个有效原因标签的案例数 | 整数及已归因率 |
| 待归因案例数 | 无有效标签且不处于归因中的案例数 | 整数及待归因率 |
| 原因种类 | 当前筛选范围内至少出现 1 次的不同标签数 | 整数 |
| 原因出现总次数 | 所有案例有效标签数量之和；一例多标签分别计数 | 整数 |
| 平均商品识别率 | 正确商品名称行数之和 ÷ 有效商品行数之和 × 100% | 保留 1 位小数 |

- 已归因率 = 已归因案例数 ÷ 问题案例数 × 100%。
- 待归因率 = 待归因案例数 ÷ 问题案例数 × 100%。
- 平均商品识别率采用汇总后的加权口径，不直接平均每个案例的百分比。
- 问题案例数为 0 时，相关比例展示“—”。

#### 3.5.4 原因标签分布与下钻

- 默认展示前 5～8 个原因标签，按原因出现次数倒序排列。
- 每项显示标签名称、出现次数、占比和横向进度条。
- 原因占比 = 当前原因出现次数 ÷ 原因出现总次数 × 100%。
- 一例多标签时每个标签分别计 1 次，各标签占比之和为 100%。

点击原因标签后打开“关联租户”抽屉，并继承当前时间、业务类型、内容类型、原因标签和归因状态筛选。

| 抽屉字段 | 计算/展示规则 |
|---|---|
| 租户名称 | 使用该原因标签的案例所属租户 |
| 问题案例数 | 该原因在该租户下关联的去重案例数 |
| 案例占比 | 该租户关联案例数 ÷ 当前原因关联案例总数 × 100% |
| 主要内容类型 | 数量最多的内容类型；并列时按图片、文件、文本排序 |
| 平均商品识别率 | 该原因、该租户关联案例的加权识别率 |
| 最近发生时间 | 最近一条关联案例的提交时间 |
| 操作 | 查看问题案例、查看租户详情 |

- “查看问题案例”进入案例页并自动带入租户、原因标签和时间范围。
- “查看租户详情”打开租户运营分析，展示指标、原因分布和案例。
- 关闭抽屉后保留原筛选和滚动位置。

#### 3.5.5 原因趋势图优化

- 使用紧凑的圆角柱状图，X 轴为日期/周期，Y 轴为问题案例数或原因出现次数。
- 柱体使用统一主题色的浅色到深色渐变，避免过重描边。
- 最新周期可用强调色，其余保持同色系。
- 周期均值使用细虚线展示，不在图内堆叠大号数字。
- 悬浮显示周期、案例数、较上一周期变化值和变化率。
- 数据点不足 2 个时不计算趋势和环比，仅展示当前值。
- 控制图表高度和卡片留白，使原因分布与趋势图视觉比例协调。

本次移除独立的“平均识别率趋势”图。平均商品识别率仅保留在汇总指标和关联租户明细中。

#### 3.5.6 租户问题排行与数据要求

| 字段 | 计算逻辑 | 交互 |
|---|---|---|
| 租户名称 | 案例所属租户 | 点击进入租户运营分析 |
| 问题案例数 | 当前范围内去重案例数 | 默认倒序 |
| 主要原因 | 出现次数最多的原因标签 | 点击按原因下钻 |
| 图片案例占比 | 图片问题案例数 ÷ 该租户问题案例数 | 百分比 |
| 平均商品识别率 | 正确商品名称行数之和 ÷ 有效商品行数之和 | 百分比 |
| 操作 | 查看分析 | 打开租户运营分析 |

数据依赖：案例 ID、租户 ID、业务类型、内容类型、提交时间、有效商品行、正确商品名称行、归因状态、原因标签关系及归因来源。汇总和下钻接口必须支持同一组筛选条件。

### 3.6 试用转化事项

#### 3.6.1 事项定义

| 事项类型 | 基础优先级 | 触发条件 | 恢复条件 | 主要操作 |
|---|---|---|---|---|
| 试用期无有效使用 | 中 | 试用开始满 72 小时，最近 72 小时有效订单数为 0 | 产生首个有效订单或试用结束 | 查看租户、转为正式 |
| 试用额度已耗尽 | 高 | 服务阶段为试用且可用额度 ≤ 0 | 可用额度 > 0 或试用结束 | 调整额度 |
| 试用即将到期 | 中 | 剩余试用时间 > 0 且 ≤ 24 小时 | 延长试用、转正式或试用结束 | 转为正式、延长试用 |
| 试用已到期 | 高 | 当前时间超过试用结束时间且仍为试用状态 | 转正式、停用或重新开通试用 | 转为正式、查看租户 |

#### 3.6.2 字段、操作与数据要求

- 剩余试用时间 = `max(试用结束时间 - 当前时间, 0)`。
- 可用额度 = 额度总量 - 已用额度；判断耗尽时使用 `≤ 0`。
- 当前检测结果展示“连续 N 小时无有效订单”“可用额度 N”“剩余 N 小时”或“已到期 N 天”。
- 触发条件只展示简明阈值，完整检测依据放入问号提示和详情抽屉。

| 操作 | 打开后的展示/字段 | 提交结果 |
|---|---|---|
| 查看租户详情 | 租户基本信息、试用周期、额度、近 7 日订单、关联事项 | 查看类抽屉，不改变状态 |
| 转为正式租户 | 生效日期、服务方案、初始额度、处理备注 | 二次确认；成功后更新租户阶段并重新评估事项 |
| 调整租户额度 | 调整方式、调整额度、生效时间、调整原因 | 写入额度流水并刷新检测结果 |
| 延长试用期 | 延长天数、调整后到期时间、调整原因 | 更新到期时间并重新评估到期事项 |

数据依赖：租户服务阶段、试用开始/结束时间、额度账户与流水、订单记录和租户负责人。

### 3.7 额度及合同履约事项

#### 3.7.1 事项定义

| 事项类型 | 基础优先级 | 触发条件 | 恢复条件 | 主要操作 |
|---|---|---|---|---|
| 可用额度不足 | 中 | 额度使用率 ≥ 80%，或可用额度比例 < 20%，或可用额度 < 配置阈值 | 所有条件均不成立且连续两个周期 | 调整额度 |
| 可用额度已耗尽 | 高 | 可用额度 ≤ 0 | 可用额度 > 0 | 调整额度 |
| 合同即将到期 | 中 | 合同剩余 0～30 天且无已生效续签合同 | 完成续签、合同终止或进入已到期 | 查看合同 |
| 合同已到期 | 高 | 当前时间超过合同结束时间且无有效续签合同 | 完成续签或合同关闭 | 查看合同 |
| 预计可用额度不足 | 中 | 近 7 日平均每日用量 > 0，预计可用天数 < 合同剩余天数 | 预计可用天数 ≥ 合同剩余天数 | 调整额度、查看合同 |
| 合同回款逾期 | 中 | 应收日期早于当前日期且待收金额 > 0 | 待收金额 = 0 或合同关闭 | 查看合同 |

#### 3.7.2 计算、操作与数据要求

- 额度使用率 = 已用额度 ÷ 额度总量 × 100%。
- 可用额度比例 = 可用额度 ÷ 额度总量 × 100%。
- 近 7 日平均每日用量 = 最近 7 个自然日额度扣减总量 ÷ 7。
- 预计可用天数 = 可用额度 ÷ 近 7 日平均每日用量；平均用量为 0 时展示“—”且不触发预计不足。
- 待收金额 = 合同应收金额 - 已确认收款金额 - 已确认退款抵扣金额。

| 操作 | 打开后的展示/字段 | 提交结果 |
|---|---|---|
| 调整租户额度 | 当前额度、调整方式、调整值、生效时间、原因 | 写入额度流水并重新评估；必须记录前后值并二次确认 |
| 查看合同详情 | 合同编号、状态、有效期、金额、已收、待收、续签关系 | 查看类抽屉；提供“前往合同管理”入口 |
| 查看租户详情 | 租户基础信息、额度趋势、合同摘要、关联事项 | 查看类抽屉 |

数据依赖：额度总量及流水、合同有效期、应收金额、应收日期、收退款流水和续签关系；开发前需确认冻结、退款和负余额口径。

### 3.8 使用活跃与识别质量事项

#### 3.8.1 事项定义

| 事项类型 | 基础优先级 | 触发条件 | 恢复条件 | 主要操作 |
|---|---|---|---|---|
| 商品名称识别率低 | 中 | 有效商品行 ≥ 20 且识别率 < 70% | 识别率 ≥ 70%，连续两个周期 | 查看分析、查看案例 |
| 商品识别率显著下降 | 中 | 当前和上一周期样本均 ≥ 20，下降 ≥ 10 个百分点 | 降幅 < 10 个百分点 | 查看分析 |
| 任务提交成功率低 | 中 | 有效任务数 ≥ 10 且成功率 < 80% | 成功率 ≥ 80%，连续两个周期 | 查看案例 |
| 失败任务数异常增长 | 中 | 当前失败数 ≥ 10 且达到上一周期的 2 倍 | 不再满足增长条件 | 查看案例 |
| 订单量异常下降 | 低 | 前 7 日订单 ≥ 10，最近 7 日低于前 7 日的 50% | 比例恢复至 ≥ 50% | 查看分析 |
| 订单量连续下降 | 低 | 最近 3 日逐日下降且第 3 日低于第 1 日的 50% | 不再连续下降 | 查看分析 |
| 调用量异常增长 | 中 | 今日调用量 ≥ 10 且大于前 7 日均值的 3 倍 | 回落至 3 倍以内 | 查看分析 |
| 长时间无有效订单 | 中 | 正式租户连续 7 个自然日无有效订单 | 产生有效订单 | 查看租户 |
| 已签约未上线 | 中 | 已签约或确认收款 14 天后仍未上线 | 更新为已上线或合同关闭 | 查看租户 |
| 群聊活跃率低 | 低 | 已绑定群聊 ≥ 10，近 30 日活跃率 < 20% | 活跃率 ≥ 20% | 查看群聊 |

#### 3.8.2 计算、操作与数据要求

- 商品名称识别率 = 正确识别商品名称的有效商品行数 ÷ 有效商品行总数 × 100%。
- 任务提交成功率 = 成功提交任务数 ÷ 有效任务总数 × 100%。
- 识别率下降百分点 = 上一周期识别率 - 当前周期识别率。
- 群聊活跃率 = 近 30 日产生有效任务的已绑定群聊数 ÷ 已绑定且启用的群聊数 × 100%。
- “下降 10 个百分点”指从 80% 降至 70%，不是下降 10%。
- 样本不足最低门槛时展示“样本不足”，不创建事项。

| 操作 | 打开后的展示/字段 | 结果 |
|---|---|---|
| 查看运营分析 | 租户指标、趋势、原因分布、同周期对比 | 打开租户运营分析并继承时间范围 |
| 查看问题案例 | 案例、内容类型、识别率、原因标签 | 进入案例页并带入租户和时间 |
| 查看租户详情 | 租户状态、合同/试用摘要、近 30 日使用情况 | 查看类抽屉 |
| 查看群聊详情 | 群聊名称、绑定状态、最近任务时间、近 30 日订单数 | 查看类抽屉 |

数据依赖：任务及结果、订单、字段级识别与人工确认结果、模型调用日志、签约/收款时间、上线状态、群聊绑定和任务记录；还需保存检测快照以判断连续变化。

## 4. 运营工作台通用规则

### 4.1 页面结构与顶部概览

- 默认选中“我的待办”和“试用转化”。
- 待办范围包括“我的待办”“全部待办”“处理记录”。
- “我的待办”为当前处理人是当前账号且未完成的事项；“全部待办”为权限范围内全部未完成事项；“处理记录”为已完成事项。

| 顶部指标 | 计算逻辑 | 点击行为 |
|---|---|---|
| 我的待处理 | 当前处理人为当前账号且状态为待处理的事项数 | 筛选我的待办和待处理 |
| 我的处理中 | 当前处理人为当前账号且状态为处理中的事项数 | 筛选我的待办和处理中 |
| 高优先级事项 | 当前处理人为当前账号、未完成且优先级为高 | 筛选高优先级 |
| 今日已完成 | 当前处理人为当前账号且完成时间属于今日 | 切换处理记录并限定今日 |

### 4.2 列表字段

| 字段 | 业务定义 | 展示与交互 |
|---|---|---|
| 优先级 | 高、中、低三级处理顺序 | 仅展示红、橙、蓝圆点；问号提示颜色含义 |
| 租户名称 | 事项所属租户的正式名称 | 可点击；同租户有其他事项时显示“另有 N 项” |
| 事项类型 | 标准事项类型名称 | 简洁状态标签 |
| 当前检测结果 | 最近一次检测采集的数值或状态 | 按比例、金额、数量或时长格式化 |
| 触发条件 | 当前事项对应的简明阈值或状态条件 | 完整公式通过问号或详情展示 |
| 最近触发时间 | 最近一次满足条件的时间 | `YYYY-MM-DD HH:mm` |
| 当前处理人 | 当前承担处理责任的账号 | 有权限时可在详情中调整 |
| 处理状态 | 待处理、处理中、已恢复待确认、已完成 | 状态标签 |
| 操作 | 事项详情、业务快捷操作和状态操作 | 同行最多展示 3 个，其余收进“更多” |

列表不展示“问题描述”和“处理时限”。问题背景、可能影响、完整触发依据和处理记录统一放入事项详情抽屉。

### 4.3 筛选、搜索与排序

| 能力 | 规则 |
|---|---|
| 日期 | 今日、近 7 天、近 30 天、自定义；按最近触发时间过滤 |
| 优先级 | 全部、高、中、低 |
| 当前处理人 | 我的待办固定当前账号；全部待办可选择人员 |
| 处理状态 | 待处理、处理中、已恢复待确认、已完成 |
| 搜索 | 按租户名称或事项类型包含匹配；忽略首尾空格 |
| 默认排序 | 优先级高到低；同级时处理中优先；再按最近触发时间倒序 |
| 空状态 | 显示“当前筛选条件下暂无待办事项”，提供清除筛选入口 |

### 4.4 事项详情与操作列统一交互

| 详情分区 | 展示内容 |
|---|---|
| 基本信息 | 租户、业务分类、事项类型、优先级、状态、当前处理人 |
| 触发详情 | 完整规则、当前值、阈值、首次/最近触发、触发次数 |
| 问题背景 | 问题描述、可能影响和关联业务对象；仅在详情展示 |
| 关联事项 | 根因事项、关联影响事项及当前状态 |
| 处理记录 | 操作人、时间、动作、备注及变更前后值 |
| 可执行操作 | 根据事项类型和账号权限动态展示 |

统一交互规则：

1. “查看”类操作优先打开右侧抽屉，减少离开当前上下文。
2. “调整/配置”类操作使用抽屉或弹窗；提交前校验，高风险操作二次确认。
3. 请求提交中禁用按钮并显示加载状态，防止重复操作。
4. 成功后提示结果并刷新当前行、概览指标、页签数量和处理记录。
5. 失败时保留已填内容并展示可理解的错误原因。
6. 关闭查看抽屉后保留筛选、排序、页码和滚动位置。
7. 无权限操作不展示；若提交时权限变化，明确提示权限不足。
8. 操作名称使用完整动宾结构，如“查看租户详情”“调整租户额度”。

### 4.5 状态流转

| 当前状态 | 操作 | 下一状态 | 必填信息 |
|---|---|---|---|
| 待处理 | 开始处理 | 处理中 | 当前处理人 |
| 处理中 | 标记完成 | 已完成 | 处理结果、处理备注 |
| 任意未完成 | 系统检测恢复 | 已恢复待确认 | 恢复时间、恢复检测值 |
| 已恢复待确认 | 确认关闭 | 已完成 | 关闭方式 |
| 已完成 | 重新打开 | 待处理 | 重新打开原因 |

所有状态变化记录操作来源（人工/系统）、操作人、时间、变更前后状态和备注。

### 4.6 同一租户多事项处理

1. **事项唯一键**：`tenant_id + item_type + object_id`；对象可为合同、群聊、信道或同步任务。
2. **重复事件合并**：唯一键相同时不新增行，只更新当前结果、最近触发时间和触发次数。
3. **跨类型并存**：不同事项分别展示，租户名称旁显示“另有 N 项”。
4. **租户总体优先级**：取该租户全部未完成事项中的最高优先级。
5. **根因关联**：若系统运行问题导致使用或转化异常，系统运行事项标记为根因，其余标记为关联影响。
6. **处理顺序**：先处理根因，再重新检测关联事项；已恢复的进入已恢复待确认，仍命中的继续保留。
7. **详情展示**：详情中显示同租户其他事项、根因关系和时间线，避免重复排查。

### 4.7 优先级规则

| 等级 | 定义 | 典型场景 |
|---|---|---|
| 高 | 已阻断核心业务，或已造成资金、履约和系统可用性风险 | 额度耗尽、合同已到期、信道离线、同步失败 |
| 中 | 尚未完全阻断，但存在明显转化、质量、续费或实施风险 | 试用即将到期、识别率低、合同即将到期、配置缺失 |
| 低 | 趋势提醒或非阻断问题，可按计划处理 | 订单下降、群聊活跃率低、通知未配置 |

页面只使用颜色圆点表达优先级：高为红色、中为橙色、低为蓝色。列表中不重复展示“高/中/低优先级”文字；悬浮圆点或表头问号时显示完整含义。

事项满足以下任一条件时上调一级，最高为高：

1. 同一事项连续 3 次检测仍满足触发条件。
2. 持续时间超过该事项类型配置的升级周期。
3. 影响多个群聊、合同、信道或业务分组。
4. 已导致有效订单无法生成、额度不可用或数据无法同步。

同一租户存在多个事项本身不直接使所有事项升级；租户总体优先级取最高值，并在排序和聚合提示中体现。事项恢复后不逐级降级，而是进入“已恢复待确认”或“已完成”。

### 4.8 检测、数据与埋点

- 经营指标建议每 5 分钟检测；合同、试用到期每小时检测；信道和同步事件触发并每分钟兜底。
- 首次命中时创建事项；持续命中时更新原事项；恢复后记录恢复事件。
- 比率类指标连续两个周期满足恢复条件后才判定恢复，避免阈值抖动。
- 测试租户、已停用租户和测试任务不参与生产事项检测。
- 阈值由后端配置并版本化，前端不得作为唯一规则来源。

本次不要求重建全系统数据体系，仅补齐相关模块缺失的数据：

| 数据类型 | 必要字段/能力 |
|---|---|
| 业务数据 | 租户、试用、额度、合同、订单、任务、识别结果、群聊、信道、同步、通知 |
| 事项数据 | 事项 ID、租户、分类、类型、对象 ID、优先级、当前值、规则版本、状态、处理人、触发时间、触发次数、根因事项 |
| 处理记录 | 操作人、动作、时间、结果、备注、变更前后值 |
| 检测快照 | 检测周期、当前值、阈值、命中结果和恢复结果 |
| 归因数据 | 案例、标签、来源、置信度、依据、模型版本和状态 |

必要前端埋点仅限关键链路：

| 事件 | 触发时机 | 业务属性 |
|---|---|---|
| `work_item_view` | 打开事项详情 | 事项 ID、租户 ID、事项类型 |
| `work_item_action_submit` | 提交快捷操作 | 操作类型、事项 ID、结果、错误码 |
| `work_item_status_change` | 开始、完成、重新打开 | 原状态、新状态、事项 ID |
| `case_content_preview` | 打开原始内容 | 案例 ID、内容类型、结果 |
| `manual_tag_save` | 保存人工标签 | 案例 ID、修改前后标签 |
| `reason_label_drill` | 点击原因标签 | 标签 ID、当前筛选快照 |

埋点不得上传原始订单内容、原始图片、完整联系方式、密钥或访问凭证。

### 4.9 通用格式

| 类型 | 展示规则 |
|---|---|
| 百分比 | 保留 1 位小数并显示 `%` |
| 金额 | 保留 2 位小数并使用千分位 |
| 数量 | 整数并使用千分位 |
| 日期时间 | `YYYY-MM-DD HH:mm` |
| 分母为 0 | 展示“—” |
| 数据缺失 | 展示“—”，通过问号或悬浮说明原因 |
| 数据延迟 | 指标问号提示最近更新时间或延迟情况 |

### 5.1 P0：本次必须完成

1. 运营工作台独立为一级菜单并作为默认首页，保留四个业务分类页签。

4. 高、中、低优先级改为颜色圆点，文字说明放入悬浮提示。
5. “问题案例”和“问题归因分析”调整为平级页签。
6. 问题案例支持文本、图片和文件原始内容预览。
7. 支持人工原因标签、AI 自动归因及重新归因。
8. 原因标签分布支持下钻到关联租户和具体问题案例。
9. 优化原因趋势图，并移除独立平均识别率趋势图。
10. 补齐运营工作台操作列各业务按钮的抽屉、表单、校验和结果反馈。
11. 原因标签管理中的常驻说明文字改为问号悬浮提示。

### 5.2 P1：与 P0 配套完成

1. 四类事项的触发、恢复和基础优先级规则。
2. 同一租户多事项合并、总体优先级和根因关联展示。
3. 事项状态流转、处理记录和关键操作审计。
4. 图片订单数、图片订单占比及排序、导出规则。
5. 原因标签管理的新增、编辑、启停和历史兼容。
6. 原因分析汇总指标、租户排行及筛选继承。
7. 关键字段问号悬浮提示和统一空值规则。

### 5.3 P2：后续优化

1. 阈值、升级周期和事项规则的后台配置能力。
2. 根因事项与关联影响事项的自动识别优化。
3. 基于历史处理结果提供负责人或处理方案建议。
4. 运营效率和事项闭环效果分析。

### 5.4 验收要点

- 登录后默认进入运营工作台和“我的待办”。
- 四个页签数量与当前待办范围和筛选结果一致。
- 列表不出现“问题描述”和“处理时限”列。
- 优先级仅以颜色圆点展示，悬浮后可查看完整说明。
- 每个行操作都有明确的打开内容、必填校验、提交状态、成功/失败反馈和数据刷新。
- 相同事项唯一键不产生重复行；同租户多事项可查看关联关系。
- 图片订单占比、识别率、归因率和原因占比可按文档公式复算。
- 原因标签点击后展示关联租户，并可继续查看对应案例。
- 原因趋势图布局紧凑、信息可读，页面不再出现平均识别率趋势图。
- 原因标签管理说明及具有特殊含义的表格字段使用问号悬浮提示。
- 人工原因标签保存后不会被 AI 自动覆盖，归因失败能够重新执行。
- 关键业务操作和状态变化均保留可审计记录。
