# 定价助手 · 观麦口径离线原型

以“对话＋列表”帮助配送业务人员选择客户、报价单与商品，查阅观麦已有资料，预览客户协议价或报价单基础价的调整。

**本交付使用虚构演示数据，未连接观麦后端或真实 AI。** “应用演示”只修改当前浏览器的数据。本次将代码与文档同步到 GitHub 的 quotation_Pricing 分支；未部署网站，也未连接真实业务环境。

## 业务背景与对象

配送业务需要同时维护多份报价单。同一客户可以关联多份报价单，同一报价单也可以服务多个客户。修改共享报价单基础价与修改某个客户的专属价格，其影响范围不同。

界面中的“客户”对应观麦门店／收货地址，以 address_id 区分；所属账号通过 user_id 关联。结算配置属于客户账号，不属于商品。客户与报价单按门店、站点、报价单单独保存关联。商品以所属报价单下的 SKU 操作，同名或同 SPU 不代表同一个修改对象。

负责人查看采购参考、报价记录、平台行情、客户资料和系统价格规则，再决定范围和调整值。系统协议价是观麦价格配置，不代表双方已经签署合同。本原型验证字段和操作流程，经营决定由使用者作出。

## 快速启动

用 Edge 或 Chrome 打开本目录 index.html，无需安装依赖。需要本地 HTTP 访问时，在本目录运行：

    python -m http.server 8080 --bind 127.0.0.1

随后打开 http://127.0.0.1:8080。样式和脚本均嵌入 HTML，无运行时网络依赖。

## 页面与操作

| 区域 | 用途 |
| --- | --- |
| 顶部客户选择 | 选择门店／收货地址，持续显示客户、报价单和调价范围 |
| 左侧关联报价单 | 仅列当前客户关联报价单；有多张时需明确选择一张 |
| 报价对话 | 输入有限范围的调价表达或打开“按条件调整”，核对预览后应用 |
| 客户与依据 | 采购参考、报价记录、市场行情、客户资料、价格规则列表 |
| 规则与调价 | 客户协议价与报价单周期调价任务 |
| 查看报价单 | 搜索名称、编码、规格，分类、分页和跨页勾选 |

默认范围是**客户专属价**。需要修改共享基础价时，明确切换为**报价单基础价**。切换客户、报价单或调价范围会清空选择并使旧预览失效。

## 五分钟试用

1. 选择 **晨禾食堂 → 日常配送报价单**，保留“客户专属价”。
2. 打开“客户与依据”查看采购参考或报价记录；打开“查看报价单”搜索编码 Q1-0001。
3. 点击“按条件调整”，勾选该商品，选择“按百分比调整”，数值填 3，基准选“报价单基础价”。填写有效日期 2026-09-30 至 2026-10-07，保留全天时段。
4. 点击“生成预览”，核对客户、报价单、商品、基础价、客户当前适用价、拟调整值和影响范围。
5. 点击“应用演示”，到“规则与调价 → 客户协议价”查看本地规则。
6. 切换“报价单基础价”，对 Q1-0004（鲜鸡蛋）预览上调 10%，查看影响范围。晨禾使用固定价、云栖使用倍率规则、桥头使用基础价，三家客户的影响不同。
7. 在“报价单周期调价”中编辑未开始任务的名称和执行时间。保存只更新设置，不模拟自动执行成功。

对话可尝试“Q1-0001按报价单基础价上调3%”。识别后仍需在表单核对商品和有效期。同名商品有多个规格时，使用商品编码或列表明确选择。

## 资料口径

| 资料 | 内容与边界 |
| --- | --- |
| 采购参考 | 最近采购价、供应商最近采购价、商品设定损耗率；价格保留接口已换算的基本销售单位 |
| 报价记录 | SKU 变更记录及适用时间段，默认近七日；不是成交历史，不补每日价格 |
| 市场行情 | 平台商品、规格、平台单位、平均／最高／最低价和数据日期；不是实时新闻 |
| 客户资料 | 门店资料、运营时间、账号结算配置、购买分析、最近订单 |
| 价格规则 | 适用客户、商品范围、计算方式、有效日期、每日时段、原生状态 |

购买分析默认演示 2026-09-01 至 2026-09-30，按下单时间。订单数、销售金额、下单金额取对应统计响应，不从最近订单列表自行汇总。最近订单独立按“近90天内最近50单”口径展示，实际演示记录可少于50条。

SKU 与客户适用价格按分转换展示，行情保留平台原金额和单位，订单与统计使用对应接口尺度。价格逐行带币种和单位，不加统一“含税元/斤”。缺失为“—”，时价未定为“待定价”。系统建议价范围仅在商品详情按基本销售单价显示，不称为 AI 推荐。

## 调价与规则

- 客户协议价采用固定值、加减值、倍数。按客户当前适用价的一次计算保存为固定价；按基础价加减或乘倍数保存为浮动规则。
- 有效期必须明确。冲突会阻止应用；多客户共用规则不能冒充仅修改当前客户。分类、SPU 上浮率、整单折扣可查看，本轮不自动覆盖。
- 取价顺序为 **阶梯价 → 客户协议价 → 时价 → 报价单固定价**。阶梯价需要数量；客户协议调价不覆盖阶梯表。上浮率或整单折扣的精确结算提示回原系统确认。
- 共享报价单调整列出全部关联客户，分别展示价格影响；固定协议客户可能不变。
- 未来日期是规则配置，不代表已经取得未来实际结算价。
- 周期调价只编辑已有未开始任务的名称、执行时间；状态、异常和执行结果分别显示，不随浏览器时钟自动推进。

本版移除 AI 倾向价／区间、单位损耗量、配送成本、自算利润／采购总重量、市场消息、微信／企微原文及核实、条件勾选及快照、助手报价版本、人工落实核验、客户独占策略和到期恢复等自行设计的流程或字段。

## 演示与保存

- 固定演示时点：**2026-09-30 10:00（北京时间）**。各类数据日期分别显示，不随电脑日期伪装成实时记录。
- 三家客户各关联两张报价单；共享日常报价单300个 SKU，其余三张各48个 SKU。
- 左下角“本地演示 · 使用说明 → 演示数据管理”可恢复300商品或加载1000商品；重置清除本版修改。
- 搜索、分类、25／50／100条分页、选择本页、选择全部匹配、跨页选择用于大商品量。分页不缩小实际应用范围。
- 使用独立存储键 guanmai-pricing-prototype-v1。旧版数据保留，不迁移为观麦对象。刷新后保留本地数据和对话，历史预览需重新生成。
- 对话是浏览器内有限语法解析，没有模型调用、API Key 或真实推理。没有跨设备同步、多人权限、服务端校验或真实任务执行。

## 源码与构建

本项目位于 `Xky114514/Xky114514.github.io` 的 `quotation_Pricing` 分支，目录为 `quotation-pricing/`。

```text
quotation-pricing/
├── index.html                # 可直接打开的完整离线界面
├── README.md
├── src/                      # 数据、取价引擎、资料视图、对话与样式源码
├── scripts/build.py          # 将源码构建为单文件 HTML
├── tests/pricing-engine.cjs   # 18 组取价、规则与批量操作测试
└── docs/                     # 设计、字段映射和试用记录
```

在 `quotation-pricing` 目录运行（Python 3 与 Node.js，无第三方依赖）：

```sh
python scripts/build.py
node tests/pricing-engine.cjs
python -m http.server 8080 --bind 127.0.0.1
```

源码修改后重新构建 `index.html`。`gm-data.js` 为虚构数据，`gm-engine.js` 处理确定性取价和冲突校验，`gm-evidence.js` 展示原生资料口径，`gm-app.js` 处理交互，`chat-intent-engine.js` 处理有限语法；没有真实 AI 调用、密钥或观麦后端代码。

仓库同步保留其他项目文件，本次不修改 `main` 分支，不自动合并或部署 GitHub Pages。
