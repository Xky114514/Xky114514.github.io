# 定价助手界面设计说明

依据用户确认的方案及后续交互要求，当前前端以对话制定报价、整单核对依据、独立管理策略为主。它是离线演示：未接入真实大模型、企微、ERP 或业务后端，客户、价格、协议及记录均为示例。

## 1. 三个主要菜单

| 菜单 | 职责 |
| --- | --- |
| 报价对话 | 提出需求、明确范围与规则、审阅调整预览、应用草稿 |
| 客户与依据 | 单选客户，查看整单五类依据，再深入商品明细与来源记录 |
| 报价策略 | 按客户管理已确认价格快照、启停时间、历史与替换记录 |

顶部始终标明客户、报价周期、版本和阶段。报价单默认折叠到侧面板，需要时打开对照“当前价／AI 参考／我的报价”。最终价独立保存，不反向改写 AI 原建议。

## 2. 对话与结构化规则共用调整流程

**明确客户及商品范围 → 生成预览 → 应用到草稿 → 整版确认。** 预览本身不修改报价；可查看匹配项、计算基准、原价与拟定价，以及保持不变的例外。

规则支持商品名称、分类、当前执行价筛选，以及百分比、固定金额、指定最终价或采用有效参考价。比例和金额调整需明确计算基准，不能默认重复叠加。自然语言仅支持已实现的规则解析；范围、单位、税价或公式不清时先澄清，不保证任意表达均可执行。每轮讨论最多追问三个关键问题。

应用后可在没有后续变更、版本未确认时撤销最近一次批量调整。报价或依据变化后，旧预览需重新生成；已确认价格、依据或经营条件变更须先创建修订版。

## 3. 整单依据与可读来源

客户选择使用单选下拉，折叠项与展开项都展示客户名、商品数及五类标签，支持键盘、Escape 和外部点击关闭。切换客户时，报价与调整上下文保持隔离。

页面不再用某个选中商品代表整单，而是展示五类汇总卡片。点击卡片列出本单每个商品的相关依据；每项均可查看来源或进入仅选该商品的调整预览。

| 整单卡片 | 商品明细保留的信息 |
| --- | --- |
| 采购与成本 | 采购参考及变化；损耗、配送等缺项明确标记 |
| 历史价格 | 当前执行价、近期成交与调整参考 |
| 市场与供应 | 人工汇集资料、规格与配送可比性、已排除状态 |
| 商户情况 | 采购量、频次、规格、配送、账期及待确认项 |
| 约定与条件 | 有效协议、数量阶梯、时价、适用时段和原系统限制 |

来源入口可阅读系统导出、企微沟通、指定外部来源、协议及业务条件的演示记录，包含来源、日期、客户、适用对象、核实状态和约束；不只是来源分类说明。

价格影响、确定程度和约束可同时存在。客观资料、AI 建议、负责人决定分开；市场区间、AI 区间、强制限制分别命名。详情保留上下沿理由、倾向价、取舍与待确认项，不设置统一因素权重。

固定协议适用时显示协议价；不足以支持区间时保留参考点和缺项；区间过宽先确认条件。自主价可超出 AI 区间，真实约束冲突另行处理。企微消息、AI 建议或手填新价均不使协议自动变更。

## 4. 报价策略与生效时段

整版确认后保存独立价格快照，可命名、设置生效时间、停用和查看历史；草稿不能直接生效。制定时的调整规则只作记录，不会到生效时间自动重复计算。

同一客户同一时段只允许一套启用策略。重叠时先展示冲突及替换影响，明确确认后再提前结束旧策略或取消其安排；其他客户不受影响，旧策略不会自动恢复。

时间按北京时间处理，开始时刻包含、结束时刻不包含。已发生的开始时间保留，停用、取消和结束各有状态与历史；历史策略通过复制重新安排。

新时段超出来源报价周期时，须重新核对整版价格及业务条件。鲜鸡蛋协议示例仅覆盖 10月1日—31日，超出协议边界不能仅靠勾选知悉启用；需先核实新约定。排期不改写原报价版本。

## 5. 版本确认、原系统执行与演示边界

确认前审阅整版具体价格、适用条件、影响客户及未解决项；接受区间不等于定价完成。新资料只更新受影响建议，已定价格保留并提示复核。

策略安排与原系统执行独立：策略启用不自动录单。确认具体版本后，由执行人员在原系统人工落实，再记录人员、时间和记录号，核验同版实际价格与适用条件；差异不能显示为核验完成。

草稿、对话、策略与版本历史保存在当前浏览器，用于演示，不代表服务器存档或跨设备同步。本交付不提供自动写回、实时行情抓取、自动改约或权限审批链；真实接入与计算校验需另行实施。
