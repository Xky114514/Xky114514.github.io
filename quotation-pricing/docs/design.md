# 定价助手界面设计说明 · 观麦口径

本版根据观麦已有客户、报价单、SKU、统计、行情和规则，保留“对话＋列表”交互。交付为离线 HTML，数据为虚构演示。本轮不接后端、不发布 GitHub、不部署网站。

## 1. 业务对象和上下文

一个客户可关联多张报价单，一张报价单也可服务多个客户。调价首先确定“哪一个收货客户、哪一张报价单、修改哪种价格”。

| 对象 | 标识和关系 |
| --- | --- |
| 客户 | 门店／收货地址 address_id，关联所属账号 user_id |
| 客户账号 | 承载结算配置，账期不归属于商品 |
| 报价单 | 独立保存币种、运营时间等原生资料 |
| 关联关系 | 门店、站点、报价单多对多关联 |
| 商品 | 操作所属报价单下的 SKU；同名或同 SPU 不合并 |
| 客户协议价 | 系统规则，包含客户、范围、计算方式、有效日期和每日时段 |
| 周期任务 | 报价单任务及其执行时间、状态、异常和结果 |

顶部持续显示客户、报价单及范围；侧栏列当前客户关联报价单，多张时必须明确选择。默认“客户专属价”，修改共享基础价需手动切换。

切换客户、报价单或调价范围时清空选择、数量及相关筛选，旧预览失效。各上下文对话独立保存；刷新后的历史预览只能阅读，须重新生成才能应用。

## 2. 页面与使用步骤

主菜单为“报价对话”“客户与依据”“规则与调价”。详细资料、商品表和调整表单按需打开，避免对话界面堆满信息。

### 报价对话

1. 选择客户、报价单和调价范围。
2. 用文字或“按条件调整”明确 SKU、计算方式、数值和基准。
3. 客户价调整填写有效日期、每日时段；跨午夜单独选择。
4. 生成预览，核对基础价、客户当前适用价、拟调整值、未处理项及影响客户。
5. 无阻止项后应用演示，查看更新后的本地商品或客户规则。

自然语言使用本地有限语法，不调用 AI。识别结果进入结构化表单确认；同名多规格需用编码或列表明确。基准、范围不明时补充，混合单位的固定金额调整需分批处理。

### 大商品量

商品选择支持名称／编码／规格搜索、分类、25／50／100条分页、选择本页、选择全部匹配和清空选择。跨页保留完整集合，预览和应用不得只处理当前屏幕。商品表滚动，预览与影响范围分页。

默认共享报价单300个 SKU，可在使用说明加载1000商品；另外三张报价单各48个 SKU。

## 3. 客户与依据口径

| 标签 | 内容与边界 |
| --- | --- |
| 采购参考 | 最近采购价、供应商最近采购价、商品设定损耗率；采购参考按基本销售单位 |
| 报价记录 | 实际 SKU 变更及下一次变更时间，默认近七日；不造每日价格，不叫客户成交价 |
| 市场行情 | 平台商品、规格、平台单位、平均／最高／最低价和日期；不推断自动可比 |
| 客户资料 | 门店资料、联系人、地址、运营时间、账号结算、购买分析及最近订单 |
| 价格规则 | 客户、报价单、商品／分类范围、计算方式、日期、每日时段、原生状态 |

客户购买分析取 /station_statistics/order/customers_analysis 的聚合响应：kv.old_order_id 是订单数，kv.account_price 是销售金额，kv.order_price 是下单金额。默认近30天、按下单时间；不从最近订单抽样重算，不新增平均金额字段。最近订单独立标记“近90天内最近50单”。

结算资料保留日结、周结、月结、自定义、半月结和原生起始日、结算日、周期长度、延后配置及日期维度，不一律解释为“对账后若干天”，不自行推导采购频次或配送要求。

币种和单位逐行展示。SKU 与客户价按分展示；采购参考已换算为基本销售单位，不再次换算；行情保留平台原金额和单位；订单与统计保留其来源尺度。缺失显示“—”，时价未定单列。系统建议价范围只在商品详情显示，按基本销售单价，不能称 AI 推荐。

完整映射见交付目录 docs/guanmai-fields.md。address_ids、规则子项 sku_id 等为本地适配字段，对接需还原原生 addresses、skus[].id，不能当作新的业务字段。

## 4. 调价和取价行为

### 客户专属价

采用固定值、加减值、倍数三种原生规则。百分比转换为倍率；以基础价计算的加减／倍率随基础价变化，以客户当前价一次计算的结果存为固定价。有效期必填。

单客户 SKU 规则可进入修改预览，保留真实日期、时段和单位。多人规则不自动拆分，分类规则不由局部规则静默覆盖。冲突按客户、范围、日期和类型检查，删除“同一客户只能一套策略”的限制。

SPU 上浮率和整单折扣可查看，本轮不模拟精确结算或覆盖。有效／未开始／无效／关闭为原生状态，与聊天核实或合同签署无关。

### 报价单基础价

只更新当前报价单指定 SKU 的基础销售价，列出所有关联客户。固定协议客户可能不变，浮动协议客户可能随基础价变化。

取价顺序为 **阶梯价 → 客户协议价 → 时价 → 报价单固定价**。阶梯价缺数量时不显示确定结果，客户协议调价不覆盖阶梯表。时价未定不能当成免费。未来日期只用于规则配置，不承诺未来结算价。

### 周期调价

列表保留名称、报价单、执行时间、状态、异常和结果。只编辑已有未开始任务的名称与执行时间，遵循原生约束。时间到达不会由页面自动标记成功；本轮没有新建／导入任务、结束时间、到期恢复或人工录单核验。

## 5. 演示边界、存储与验收

固定时点为 **2026-09-30 10:00（北京时间）**，各来源日期分别保留。没有真实 AI、观麦接口、企微／微信或任务队列连接，不抓新闻、不发消息、不写回业务系统。

独立本地键 guanmai-pricing-prototype-v1 保存本版数据和对话。旧版记录保留但不迁移；预览是当前数据上的临时结果，变化后必须重做。重置只影响本版修改。

旧版 AI 区间／倾向价、单位损耗量、配送成本、自算利润／采购重量、市场消息、聊天及核实、勾选条件、条件快照、助手版本、客户独占策略、人工落实核验已移除。

验收涵盖多对多、同名跨单不串价、固定／浮动客户影响、共享规则保护、阶梯数量与时价、单位币种缺失值、报价记录与成交记录区别、任务状态独立、300／1000商品批选、桌面与窄屏。实际结果见交付目录 docs/user-trial.md；离线通过不等于服务端权限、并发、校验和任务已接入。
