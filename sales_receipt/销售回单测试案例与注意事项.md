# 销售回单测试案例与注意事项

## 一、测试前准备

准备一张包含以下商品的销售订单：

- 下单数与出库数相同的商品。
- 下单数与出库数不同的商品。
- 实际少收、实际多收、完全未收到的商品。
- 数量一致但存在破损、质量问题的商品。

## 二、核心测试案例

| 场景 | 示例 | 预期结果 |
|---|---|---|
| 正常签收 | 出库 10，实收 10 | 差异数为 0；实收框不标红；商品不自动进入售后。 |
| 实际少收 | 出库 10，实收 6 | 差异数为 4；实收框标红并显示提示；自动进入售后，默认“仅退款/商品异常”，售后数为 4。 |
| 实际多收 | 出库 10，实收 12 | 差异数为 -2；实收框标红并显示提示；自动进入售后，售后数为 -2。 |
| 完全未收到 | 出库 10，实收 0 | 差异数为 10，并自动进入售后；`0`必须作为有效数量处理。 |
| 实收数未填写 | 实收数为空 | 不计算有效差异，提示待核对，并阻止提交。 |
| 下单数与出库数不同 | 下单 12，出库 10，实收 6 | 差异数必须为 4，不能按下单数计算成 6。 |
| 数量一致但需要售后 | 出库 10，实收 10，商品破损 | 可人工新增该商品的售后；填写售后类型、原因和非 0 售后数后可提交。 |
| 修改实收数 | 先填 6，再改回 10 | 差异从 4 变为 0；未人工修改的自动售后随之移除。 |
| 退货退款 | 选择“退货退款/商品退货” | 必须填写原因和售后数；提交成功后按业务规则生成退货单据。 |
| 提交校验 | 原因空白、售后数为 0、数量格式错误 | 阻止提交并定位错误字段；已填写内容不丢失。 |
| 更换订单 | 已填写实收数或售后后更换订单 | 确认后按新订单重新加载商品并清理未提交售后；取消时保留原内容。 |
| 已完成回单 | 打开已提交回单 | 内容只读；不出现“继续售后”“提交后续售后”等二次售后入口。 |

## 三、重点注意事项

1. **计算口径**：差异数始终为`出库数－实收数`，下单数只用于对照。
2. **正负含义**：售后数默认等于差异数；正数表示需要多送，负数表示需要少送。
3. **空值与零不同**：空白表示未确认，`0`表示明确未收到。
4. **自动售后**：出库数与实收数不一致时，系统自动加入售后，默认类型为“仅退款/商品异常”。
5. **单条限制**：同一商品只能保留一条售后记录和一个售后类型，不能重复添加。
6. **提交前可调整**：商品可从售后中移除，也可重新添加；提交后结果锁定。
7. **功能范围**：当前销售回单不处理非商品异常，也不支持提交后的二次售后。
8. **保存与提交**：保存仅保留草稿；提交才形成正式回单和售后结果。
9. **时间展示**：下单时间、收货时间只展示到分钟，不显示秒。
10. **整体校验**：任一商品校验失败时，本次回单和售后均不能部分提交。

## 四、给售后的简短讲解口径

> 销售回单以出库数核对商户实收数。出库数和实收数不一致时，系统会标红并自动加入售后，差异数和默认售后数都按“出库数－实收数”计算。一个商品只允许一条售后，提交后内容锁定，不支持在回单中再次追加售后。测试时重点检查少收、多收、实收为 0、实收为空以及下单数与出库数不一致这几种情况。
