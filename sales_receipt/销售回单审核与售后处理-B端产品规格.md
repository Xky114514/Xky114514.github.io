# 销售回单审核与售后处理 B 端产品规格

## 1. 文档信息

- 需求名称：销售回单审核与追加售后处理
- 版本：V2.5
- 日期：2026-08-25
- 范围：回单任务列表、待处理详情、已提交详情、商品售后、非商品异常

## 2. 目标与原则

销售回单是唯一主单据。操作员在同一页面完成签收核对和售后处理，不创建独立“售后单”，不区分“正常签收／售后单处理”模式。

1. 保持现有回单界面结构，不大幅改版。
2. 商品售后由人工主动选择，不根据下单数、签收数或差异数自动生成。
3. 同一商品可登记多条售后动作，也可在回单提交后继续追加售后。
4. 非商品异常属于回单任务，一张回单可登记多条，不绑定商品。
5. 原回单与历史售后只读留痕；后续售后只能追加，不能覆盖历史。
6. 页面只展示业务操作、必要状态与校验反馈，不增加解释性文案。

## 3. 业务对象

```text
销售回单任务 1 ── 1 销售订单提交快照
销售回单任务 1 ── N 回单商品行
回单商品行 1 ── N 商品售后动作
销售回单任务 1 ── N 非商品异常
已提交回单 1 ── N 后续售后提交批次
后续售后提交批次 1 ── N 商品售后动作
```

商品售后与签收差异相互独立：有差异的商品可以不做售后，无差异的商品也可以登记售后。

## 4. 状态模型

| 对象 | 状态 | 规则 |
|---|---|---|
| 回单任务 | 待处理 | 可核对商品、维护售后、改绑订单、保存或提交 |
| 回单任务 | 已完成／已提交 | 原回单只读；允许继续追加商品售后 |
| 回单任务 | 已作废 | 不可继续处理 |
| 售后判断 | 未判断 | 不允许提交回单 |
| 售后判断 | 已登记售后 | 至少存在一条有效商品售后或非商品异常 |
| 售后判断 | 已确认无需售后 | 由操作员明确确认 |
| 售后动作 | 编辑中 | 当前轮次可编辑、删除和校验 |
| 售后动作 | 已提交 | 只读留痕，不可修改或删除 |

“已完成／已提交”仅表示回单审核已结束，不表示该销售订单不能继续发生售后。

## 5. 页面与交互

### 5.1 回单任务列表

列表固定展示：状态、时间、来源、商户、操作员、处理概况、操作。

- 待处理任务进入审核页，可保存、提交或填写原因作废。
- 已完成任务进入只读详情页，可查看历史并继续售后。
- 处理概况只显示关键业务结果，不扩展售后明细列。

![销售回单任务列表](./docs/images/receipt-list.png)

### 5.2 商品核对

主表固定为 7 列：序号、订单商品、识别商品、下单数、签收数、差异数、备注。

| 字段 | 规则 |
|---|---|
| 订单商品 | 来自当前关联销售订单，保持订单顺序 |
| 识别商品 | AI 识别结果，用于辅助一一匹配 |
| 下单数 | 只读，任何售后均不修改 |
| 签收数 | 空值表示未确认；明确 `0` 表示零签收；最多两位小数 |
| 差异数 | 下单数－签收数，仅作核对参考 |
| 备注 | 随回单草稿保存 |

订单外或重复识别商品不进入主商品表。开启销售实收时，回单提交后按签收数更新销售订单出库数；下单数保持不变。

![销售回单商品核对](./docs/images/receipt-review-products.png)

### 5.3 页内售后处理

“商品核对”和“售后处理”位于同一审核区，通过标签切换，不打开独立弹窗。

#### 商品售后

- 从当前销售订单商品中选择售后商品。
- 按商品分组；商品名称、编码、下单数、签收数、差异数只在组头展示一次。
- 同一商品可通过“添加售后类型”登记多条动作。
- 动作字段：售后类型、售后原因、处理数量。
- 类型支持“商品异常—异常”和“商品异常—退货”。
- 新增动作数量默认留空，不引用差异数。
- 删除动作只删除售后记录，不删除主表商品。
- 商品分组支持搜索、单组折叠及全部展开／收起。
- 已取消商品数／处理数汇总标签及“全部、待完善、已完善”筛选。

#### 非商品异常

- 归属当前回单任务，不挂在商品行下。
- 支持一张回单新增多条。
- 字段包括异常原因、责任部门、跟进部门、处理方式、金额方向、金额、处理状态、描述。
- 已取消区块标题后的数量汇总。

![销售回单页内售后处理](./docs/images/receipt-review-after-sales.png)

### 5.4 大量商品

| 商品数 | 页面策略 |
|---|---|
| 少于 30 条 | 保持简洁表格 |
| 30 条及以上 | 启用搜索、快捷筛选、问题优先排序、问题导航、批量操作和固定表头 |

批量操作仅作用于明确选中的商品，支持撤销。禁止批量补零、按差异生成售后数量或跨单位批量填数量。搜索、筛选、排序和滚动不得丢失草稿、选择及错误状态；最终提交始终校验全量数据。

![大量商品审核](./docs/images/receipt-review-large-order.png)

### 5.5 已提交后的后续售后

已完成页保留“继续售后”入口，仍在当前回单页的售后标签中处理。

1. 原回单、签收数、差异数、关联订单、非商品异常和原提交信息保持只读。
2. 历史售后动作显示“已提交”，不可编辑或删除。
3. 已有售后商品可继续“添加售后类型”；其他订单商品可通过“新增售后商品”加入。
4. 本轮仅校验新增动作；点击“提交后续售后”后，新动作锁定为历史记录。
5. 同一商品可跨多个轮次重复售后，不按商品 ID 覆盖旧动作。
6. 每轮保留动作 ID、提交人、提交时间、同步结果；退货动作可生成新的退货入库单号。
7. 提交后可再次发起下一轮，刷新页面后历史记录仍保留。

![已提交回单继续售后](./docs/images/receipt-completed-followup.png)

## 6. 订单关联与改绑

- 未关联销售订单时，售后处理和确认提交不可用。
- 待处理回单允许改绑；存在人工修改或售后草稿时，确认前说明影响。
- 改绑后按新订单重建商品明细，清空原商品售后；非商品异常保留并标记待重新确认。
- 取消或失败时恢复原关联及草稿，不静默迁移售后数据。
- 已提交回单不可改绑。

## 7. 保存、提交与数据

待处理回单提交载荷：

```text
receiptRows: 签收商品数组
afterSalesActions: 商品售后动作数组
nonProductExceptions: 任务级非商品异常数组
afterSalesDecision: 售后判断状态
```

后续售后提交载荷至少包含：回单 ID、销售订单 ID、提交批次 ID、动作 ID、商品 ID、售后类型、原因、处理数量、提交人、提交时间和同步结果。

提交顺序：

1. 校验回单基础字段与全量商品。
2. 校验售后判断状态。
3. 校验全部当前可编辑的商品售后动作。
4. 初次提交校验全部非商品异常；后续售后不修改历史非商品异常。
5. 同步成功后锁定本次记录并展示整体结果。

## 8. 验收标准

1. 主商品表保持 7 列，售后不侵入商品行。
2. 空签收数阻止提交，明确 `0` 可保存和提交。
3. 同一商品可登记多条售后动作，处理数量不按差异自动生成。
4. 非商品异常可登记多条且不绑定商品。
5. 售后处理全程位于回单审核页内，无独立售后弹窗或独立售后单实体。
6. 商品售后区不展示商品／处理汇总标签、完整性筛选；非商品异常区不展示数量标签。
7. 大量商品场景可搜索、筛选、定位和批量处理，且全量校验不遗漏隐藏数据。
8. 已提交回单的主数据与历史售后不可修改。
9. 已提交后可对同一商品追加新动作；提交后锁定，刷新可追溯，并可继续下一轮。
10. 后续售后不修改原回单签收结果、任务状态、关联订单和非商品异常。
