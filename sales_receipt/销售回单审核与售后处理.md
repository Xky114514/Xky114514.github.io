# 销售回单审核产品说明


## 2. 业务定义

销售回单用于核对销售订单的实际收货结果，并在同一审核页登记商品售后。系统以销售订单的实际出库商品为核对范围，以出库数和实收数计算差异；下单数仅用于追溯原始订单，不参与差异及售后数量计算。

核心原则：

- 原始图片、文件和消息只读保留，作为审核依据。
- 回单必须关联有效销售订单后才能提交。
- 商品核对和售后在同一页面完成，不使用独立弹窗或标签页切换。
- 一个商品只保留一个售后类型和一条售后记录。
- 一张回单只形成一份售后结果；售后提交后锁定，不支持二次或多轮追加。
- 非商品异常不在本期销售回单审核范围内。

## 3. 页面与操作流程

1. 查看左侧原始材料，核对群聊、文件或图片内容。
2. 确认系统自动关联的销售订单；必要时使用查询订单更换关联。
3. 核对商户、订单号、下单时间、收货时间和备注。时间精确到分钟，不展示秒。
4. 在商品核对表确认识别商品及实收数，系统实时计算差异数。
5. 对需要处理的商品维护售后类型、原因和售后数；也可从当前订单商品中新增售后商品。
6. 点击保存保留草稿，点击提交完成当前回单及售后校验。
7. 售后编辑页使用“取消”和“提交”；取消不保存当前变更，提交后结果只读，不能再次发起二次售后。

## 4. 字段说明

### 4.1 基础信息

| 字段 | 含义 | 规则 |
| --- | --- | --- |
| 商户 | 当前销售订单所属商户 | 由识别或关联订单带出；提交前可用于查询订单。 |
| 订单号 | 当前关联销售订单编号 | 必须对应有效销售订单；更换订单后重新加载商品。 |
| 下单时间 | 订单创建时间范围 | 开始时间不得晚于结束时间；精确到分钟。 |
| 收货时间 | 订单计划或实际收货时间范围 | 开始时间不得晚于结束时间；精确到分钟。 |
| 备注 | 整张回单补充信息 | 非必填，记录字迹模糊、破损或人工核对依据。 |

### 4.2 商品核对

| 字段 | 含义 | 规则 |
| --- | --- | --- |
| 订单商品 | 关联订单中的商品 | 只读，按订单商品顺序展示。 |
| 识别商品 | 从回单材料识别出的商品 | 未识别时展示 `--`，由审核员结合原始材料核对。 |
| 下单数 | 商户最初下单数量 | 只读，仅供追溯，不参与差异计算。 |
| 出库数 | 仓库实际发出数量 | 只读，是差异和售后计算基准。 |
| 实收数 | 商户实际收到数量 | 可录入非负数；空值表示未确认，`0` 表示明确未收到。 |
| 差异数 | 出库与实收的数量差 | 自动计算并保留正负号；表头提示“差异数 = 出库数 - 实收数”。 |
| 备注 | 商品级核对说明 | 非必填。 |

### 4.3 售后

| 字段 | 含义 | 规则 |
| --- | --- | --- |
| 商品 | 当前订单中需要售后的商品 | 同一商品只能出现一次，可在提交前移除。 |
| 出库数 | 商品实际出库数量 | 只读。 |
| 实收数 | 商户实际收到数量 | 只读，与商品核对表保持一致。 |
| 售后类型 | 本次商品处理类型 | 单选：`仅退款/商品异常`、`退货退款/商品退货`。 |
| 售后原因 | 处理原因 | 必填，可选择预设原因或输入，最多 100 个字符。 |
| 售后数 | 本次需要处理的数量 | 默认取差异数，可人工修改；必须为非 0 数值，最多两位小数。表头提示“售后数 = 差异数；正数表示多送，负数表示少送”。 |

## 5. 计算逻辑

### 5.1 差异数

`差异数 = 出库数 - 实收数`

- 差异数 `> 0`：实际少收，系统自动将商品加入售后。
- 差异数 `= 0`：出库与实收一致，不自动加入售后。
- 差异数 `< 0`：实际多收，系统自动将商品加入售后。
- 实收数为空或格式非法时，不生成有效差异数。

### 5.2 售后数

售后数创建时默认等于当前差异数，并保留正负号：

- 正数：表示后续需要多送对应数量。
- 负数：表示后续需要少送对应数量。
- `0` 不构成有效售后，不能提交。
- 人工修改实收数后，系统自动生成的售后数同步更新；人工修改过的售后记录不强制覆盖。

示例：出库 `10` 斤、实收 `6` 斤，则差异数为 `4` 斤，默认售后数为 `4` 斤，表示需多送 `4` 斤；出库 `10` 斤、实收 `12` 斤，则差异数和默认售后数均为 `-2` 斤，表示需少送 `2` 斤。

## 6. 自动售后规则

- 实收数与出库数不一致时，实收输入框标红并显示提示图标。
- 系统自动为该商品建立一条售后记录，默认类型为“仅退款/商品异常”，售后数取差异数。
- 实收数恢复为与出库数一致时，未被人工修改的自动售后记录自动移除。
- 操作员可修改售后类型、原因和售后数；人工修改后不再用系统默认值强制覆盖。
- 差异为 `0` 的商品仍可人工加入售后，用于处理数量一致但存在质量、破损等问题的场景；此时必须人工填写非 0 售后数。

## 7. 校验与异常处理

| 场景 | 系统处理 |
| --- | --- |
| 未关联销售订单 | 禁止提交，提示先选择销售订单。 |
| 下单或收货开始时间晚于结束时间 | 阻止查询或提交，并定位对应时间字段。 |
| 实收数为空 | 标记待核对，禁止最终提交。 |
| 实收数为负数、超过两位小数或含非法字符 | 输入框标错，不计算差异。 |
| 售后类型为空 | 阻止提交并定位售后类型。 |
| 售后原因为空或超过 100 字 | 阻止提交并定位售后原因。 |
| 售后数为空、为 `0`、格式非法或超过两位小数 | 阻止提交并定位售后数。 |
| 商品已存在售后记录 | 不重复添加，避免同一商品产生多行。 |
| 更换关联订单 | 重新生成商品明细并清理未提交售后；取消或失败时保留原数据。 |
| 提交失败 | 回单和售后均不部分生效，保留当前填写内容供修正后重试。 |

## 8. 边界情况

- 下单数可以与出库数不同，回单差异始终以出库数为准。
- 出库数可以大于或小于下单数，不作为回单错误。
- 实收数允许大于出库数，此时差异数和售后数为负数。
- 实收数 `0` 与空值必须区分：`0` 可计算差异，空值不可计算。
- 不同商品单位分别计算，不跨单位汇总数量。
- 数量精度遵循商品配置，本原型最多展示和录入两位小数。
- 大量商品场景保留搜索、问题筛选和定位能力；筛选不改变未显示商品的草稿值。
- 售后提交后历史结果只读，页面不再提供“继续售后”“提交后续售后”等二次售后入口。

## 9. 提交结果

- 回单提交成功后记录提交人、提交时间和同步结果。
- 商品核对结果与售后结果同时形成提交快照。
- 售后类型为“退货退款/商品退货”时，按业务配置生成对应退货单据。
- 已提交结果不可修改或删除；如业务确需再次处理，应在销售订单的其他售后入口新建独立业务单据，不在销售回单中追加。

## 10. 验收要点

1. 下单时间和收货时间均只显示到分钟。
2. 模块标题统一显示“售后”。
3. 商品核对表展示下单数、出库数、实收数和差异数。
4. 差异数表头提示公式，修改实收数后差异实时更新。
5. 售后数表头展示公式及正负语义；自动售后默认数值等于差异数。
6. 售后操作按钮为“取消”“提交”，不出现“提交后续售后”。
7. 已提交售后不允许再次追加，页面无“继续售后”入口。
