# 销售回单审核业务说明

## 1. 文档信息

- 版本：V2.5
- 日期：2026-08-25
- 状态：按当前确认需求实现
- 适用范围：销售回单待处理详情、已完成详情、审核列表及观麦同步

## 2. 业务目标

销售回单是唯一单据对象。审核员在同一张回单内确认签收事实，维护商品售后和非商品异常；系统不创建独立“售后单”，也不设置“正常签收／售后单处理”模式。

核心原则：

1. 主表保持七列，不因售后处理改变基本结构。
2. 未识别、未填写与明确填写 `0` 是不同状态。
3. 商品售后由审核员主动选择，不根据下单数、签收数或差异数自动决定。
4. 售后处理在当前审核页内完成，按商品分组；同一商品可以登记多条售后动作。
5. 页面只展示业务字段、操作及必要的状态和校验反馈，不增加流程解释文案。
6. 商品较多时渐进增强操作能力，不另建“大单页面”。
7. 回单提交后可继续追加商品售后；原回单和历史动作不可修改，后续动作独立提交并留痕。

## 3. 业务对象

```text
销售回单 1 —— 1 销售订单（提交时）
销售回单 1 —— N 回单商品行
销售回单商品行 1 —— 0..N 商品售后动作
销售回单 1 —— 0..N 非商品异常
```

- 回单商品行记录下单数、识别签收数、人工确认签收数及备注。
- 商品售后按商品分组展示，商品信息只出现一次；组内动作分别记录处理类型、原因和处理数量。
- 非商品异常不保存商品 ID，独立记录责任、跟进和金额影响。
- 回单任务状态、整体同步结果和非商品异常处理状态分别展示。

## 4. 回单商品与核对状态

主表固定展示：序号、订单商品、识别商品、下单数、签收数、差异数、备注。

### 4.1 签收数

| 状态 | 数据表现 | 规则 |
|---|---|---|
| 未识别／待确认 | 空值 | 不参与差异计算，属于待核对项 |
| 明确零签收 | `0` | 审核员或可靠识别结果明确给出，可参与计算 |
| 有效数量 | 大于 `0` | 最多两位小数，不允许负数 |

- 系统不得把空值、无效值或未识别值转换为 `0`。
- 存在未确认签收数时不得最终提交。
- `差异数 = 下单数 - 签收数`，仅在签收数有效时计算；否则展示为待确认状态。
- 差异数只作核对参考，不自动生成售后动作或售后数量。

### 4.2 待核对项

以下情况进入待核对：

- 签收数为空、格式错误或超出业务范围；
- 商品未匹配或重复识别；
- 售后动作、非商品异常字段不完整；
- 关联订单变化后尚未重新确认的数据。

待核对必须由明确操作消除，不能以滚动浏览代替确认。

## 5. 售后处理

### 5.1 售后判断状态

回单内部保留三态，页面不增加模式切换：

| 状态 | 含义 | 提交规则 |
|---|---|---|
| 未判断 | 尚未完成售后判断 | 不允许最终提交 |
| 已登记售后 | 至少存在一条有效商品售后或非商品异常 | 按明细校验 |
| 已确认无需售后 | 审核员明确确认本回单无需售后 | 可提交 |

删除最后一条售后数据后，状态恢复为“未判断”，不得自动认定为无需售后。

### 5.2 商品售后动作

每条动作包含：商品、售后类型、售后原因、处理数量。售后类型支持“商品异常—异常”和“商品异常—退货”。

1. 商品范围为当前关联销售订单的全部商品，不按差异过滤。
2. 商品核对与售后处理位于同一审核区，通过标签页切换，不打开独立售后弹窗。
3. 售后区按商品分组；商品名称、编码、下单数、签收数和差异数只在分组头展示一次。
4. 同一商品允许存在多条售后动作，包括不同类型或同类型不同原因；通过组内“添加售后类型”新增。
5. 新增动作时处理数量保持空值，不以差异绝对值自动填充。
6. 修改签收数只更新差异，不改变已选商品、动作数量和原因。
7. 删除单条动作不删除主表商品；删除最后一条动作时移除对应售后商品分组。
8. 每条动作独立校验；处理数量必须大于 `0`，最多两位小数。

### 5.3 非商品异常

每条非商品异常包含：异常原因、责任部门、跟进部门、处理方式、金额方向、金额、描述和处理状态。

| 字段 | 规则 |
|---|---|
| 异常原因 | 必填，最多 100 个字符 |
| 责任部门、跟进部门 | 从当前租户组织中选择，必填 |
| 处理方式 | 必选 |
| 金额方向 | 增加、扣减、无金额影响，必选 |
| 金额 | 退款、补差价或金额方向非“无金额影响”时必填且大于 0；补送、无需处理等无金额动作可为空或为 0 |
| 描述 | 必填，最多 200 个字符 |
| 处理状态 | 待跟进、处理中、已完成、无需处理 |

- 金额汇总展示金额数值，异常明细分别保留增加、扣减或无金额方向。
- 处理状态属于非商品异常，不新建“售后单”实体。
- 更换关联订单时，任务级非商品异常继续保留，但标记为待重新确认。

## 6. 大量商品交互

### 6.1 渐进增强

| 商品数 | 交互策略 |
|---|---|
| 少于 30 条 | 保持当前简洁表格 |
| 30 条及以上 | 展示搜索、快捷筛选、排序、问题导航和批量入口；固定表头及关键操作区 |

页面不展示“大单模式”说明。

### 6.2 搜索、筛选与定位

- 搜索范围：订单商品、识别商品、商品编码。
- 快捷筛选：全部、待核对、有差异、未识别、已修改、已售后。
- 排序：订单顺序、问题优先、差异绝对值。
- 支持上一条／下一条待核对项，并在筛选后保持当前焦点。
- 原始材料与商品行支持双向定位；仅在用户点击时联动，避免双侧滚动相互干扰。
- 售后工作区支持按商品名称、识别名称和编码搜索。
- 售后商品分组支持逐组折叠和全部展开／收起；默认只展示已经加入售后的商品。

### 6.3 安全批量操作

允许：

- 选择当前筛选结果；
- 批量标记已核对；
- 批量填写相同备注；
- 批量加入售后，再逐条完善处理数量；
- 撤销最近一次批量操作。

禁止：

- 将未识别数量批量填为 `0`；
- 根据差异批量生成售后数量；
- 跨不同单位批量填写相同数量；
- 将“全选”表述为不明确的跨筛选、跨页或跨数据集选择。

### 6.4 数据保持与校验

- 商品行和售后动作使用稳定 ID 关联。
- 搜索、筛选和排序不清空已填写值、已选状态或错误状态。
- 提交校验始终遍历全部商品，不能只校验当前筛选结果。

## 7. 订单改绑

允许审核员在待处理状态下更换关联订单，不因曾修改签收数或备注而永久锁死。

改绑前必须展示影响并二次确认：

1. 回单商品行按新订单重建；
2. 原商品售后动作清空，不得静默迁移；
3. 非商品异常保留并标记为待重新确认；
4. 取消确认时不改变任何数据。

未关联订单时，“售后处理”和“确认提交”不可用。

## 8. 保存、全量校验与提交

### 8.1 草稿

- 回单商品、售后判断状态、商品售后动作和非商品异常分别保存。
- 草稿使用商品行 ID 和动作 ID 关联，筛选和排序不改变业务数据。
- 刷新后恢复最近草稿，不自动补零、不自动加入差异商品。

### 8.2 全量防漏校验

提交校验必须覆盖当前回单全量数据：

1. 校验任务状态、关联订单及全量签收数。
2. 校验所有强制待核对项已经处理。
3. 校验售后判断状态不是“未判断”。
4. 逐条校验全部商品售后动作，允许同商品多动作，不以商品 ID 去重。
5. 逐条校验全部非商品异常的条件必填和处理状态。
6. 校验失败时自动切换到对应筛选并定位首个错误，支持前后导航。
7. 筛选隐藏或批量选择外的数据同样必须参与校验。

提交载荷分离：

```text
receiptRows: 签收商品数组
afterSalesActions: 商品售后动作数组（rows 保留为兼容别名）
nonProductExceptions: 任务级非商品异常数组
afterSalesDecision: 售后判断状态及确认信息
```

### 8.3 状态与结果

| 状态维度 | 可选值 |
|---|---|
| 任务状态 | 待处理、已完成、已作废 |
| 整体同步结果 | 同步中、已同步 |
| 处理状态 | 待跟进、处理中、已完成、无需处理 |

- 确认提交后任务进入“已完成”，并展示整体同步结果。
- 非商品异常的处理状态独立保留，不影响回单主表结构。
- “已完成”表示回单审核已经提交，不阻断后续商品售后；每次后续售后提交均形成独立、不可覆盖的处理记录。

## 9. 作废

- 待处理回单不直接删除，填写原因后标记为“已作废”。
- 已完成回单不可作废。
- 作废后列表更新任务状态和处理概况，不再展示作废入口。

## 10. 已完成页与追溯

已完成页保持七列签收快照。下列内容只读展示：

- 提交时关联订单；
- 原始识别值、人工确认值和差异；
- 售后判断状态、全部商品售后动作和非商品异常；
- 提交人、提交时间和整体同步结果；
- 非商品异常处理状态及退货入库单号。

已完成页的数据来源为提交快照，不随商品、组织或订单主数据后续变化而改写。页面同时保留“继续售后”入口，规则如下：

1. 历史商品售后动作以“已提交”状态展示，不允许编辑或删除。
2. 同一商品可继续添加新的售后类型；尚无售后记录的订单商品也可加入。
3. 后续售后只校验本次新增动作，提交后锁定，并追加到该回单的售后历史中。
4. 后续售后不修改原签收数、差异数、关联订单、非商品异常及原回单提交信息。
5. 每轮后续售后保留动作 ID、提交人、提交时间和同步结果；退货动作可生成新的退货入库单号。
6. 后续售后仍在当前回单页内完成，不打开独立售后弹窗。

## 11. 验收标准

1. 空签收数保持空值且阻止提交，明确输入 `0` 可正常保存和提交。
2. 差异数只在签收数有效时计算，且不自动生成售后商品或数量。
3. 回单售后判断支持“未判断、已登记售后、已确认无需售后”，删除最后一条售后后恢复未判断。
4. 同一商品只展示一个售后分组，组内可新增多条售后动作，各动作可独立编辑、删除和校验。
5. 非商品异常支持金额方向和条件必填；无金额动作允许金额为空或为 0。
6. 任务状态、整体同步结果和非商品异常处理状态分别展示。
7. 安全改绑有影响确认和可取消路径，不静默迁移商品售后。
8. 待处理回单支持填写原因后作废，已完成回单不可作废。
9. 商品达到 30 条时出现搜索、筛选、排序、问题导航和批量工具。
10. 搜索、筛选、排序和滚动后，填写值、选择状态及错误状态均保持。
11. 批量操作仅作用于明确选择范围，不能批量补零或按差异生成售后数量，并支持撤销。
12. 提交始终校验全量商品和售后数据，能定位被筛选隐藏的错误项。
13. 已完成页只读展示签收快照、历史售后、提交信息和整体同步结果，同时允许追加商品售后。
14. 页面保持原有布局与七列主表；售后处理在审核页内按商品分组完成，不增加独立售后弹窗、独立“售后单”实体或无必要说明文字。
15. 后续售后只新增、不覆盖历史；提交后转为只读，刷新后仍可追溯，并可继续发起下一轮。

## 12. 废止规则

以下规则不再作为实现或验收依据：

1. 将未识别、空值或解析失败的签收数转换为 `0`。
2. 仅以售后数据是否为空推导“无需售后”，或允许未判断状态直接提交。
3. 限制同一商品只能有一条售后动作。
4. 根据差异自动选择售后商品或填写处理数量。
5. 将“非商品异常”作为商品售后类型或绑定到商品行。
6. 将非商品异常处理状态混入回单任务状态。
7. 商品修改后永久禁止改绑订单。
8. 直接删除待处理或已完成回单。
9. 只校验当前筛选结果中的数据。
10. 使用独立“售后单”实体或“正常签收／售后单处理”模式。
